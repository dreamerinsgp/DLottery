## 公网部署更新——2026-09-14

已部署 Railway 前端、Go 后端和 PostgreSQL，以及 Ethereum Sepolia 上的测试代币、抽奖合约和 VRF 适配器。部署期间，生产构建、17 个合约测试以及带竞态检测的 Go/PostgreSQL 测试通过。在线水龙头经浏览器交易准确铸造了 1,000 测试 USD8，桌面和手机检查通过。真实 VRF 请求产生幸运号码 9，50 USD8 奖池滚入下一轮。API 数据与相同索引区块的合约读取一致。三个合约在 Sourcify 均获得创建字节码和运行时字节码的精确匹配。

详见[部署记录](sepolia-assessment.zh-CN.md)、[交易证据](sepolia-evidence.json)及[带时间的 API 快照](review-snapshot.json)。这部分与下文早期本地验证分开记录。该次公网演示未覆盖真实领奖和取消退款，这些路径在本地验证。浏览器自动化使用可控的钱包桥接，不是独立安装的 MetaMask 扩展。仓库没有成品录屏，但提供[录屏脚本](demo-recording.zh-CN.md)。

## 早期本地验证的限制

- 该 WSL 环境未提供可用 Linux Docker daemon。本地解析并验证了 Compose，后端使用容器同样的 CGO 设置构建，但没有在本机运行 Docker 镜像或 `docker compose up`。之后 Railway 的容器部署验证单独记录于上文。
- 2026-09-08 尚未提供公网凭据，VRF 只通过本地协调器测试合约验证。上文 2026-09-14 的 Sepolia 部署已补足 Sepolia 的真实回调验证；BSC 测试网部署仍未验证。
- 浏览器自动化使用可控的注入钱包，不是单独安装的钱包扩展。公网人工评审应核对所用钱包扩展、RPC 和订阅的实际组合。
- 这些是实现与测试证据，不是外部智能合约审计。[运维指南](operations.zh-CN.md)说明了随机数提供方永久不可用时的行为：原请求保持等待，系统没有特权重抽功能。
